# MDX 编写注意事项

在 Astro 项目中编写 `.mdx` 文件时，有几个常见陷阱会导致解析错误或渲染异常。编写前请务必阅读以下规则。

## 1. 不要使用 HTML 注释

**错误写法：**
```mdx
<!-- 这是注释 -->
```

**原因：** MDX 不支持 `<!-- -->` 形式的 HTML 注释。解析器会报错：
```
Unexpected character ! (U+0021) before name...
```
即使注释写在 SVG 或 JSX 元素内部，也会触发解析错误。

**替代方案：**
- MDX 注释：`{/* 这是注释 */}` （仅在 JSX 表达式上下文中有效）
- 直接删除无用注释，保持文件简洁

## 2. 不要在 MDX 中插入 `<script>` 标签内的代码

**错误写法：**
```mdx
<script>
  // 内联 JavaScript 代码
  const x = 1;
</script>
```

**原因：** MDX 解析器会尝试将 `<script>` 标签内部的内容作为 MDX/JSX 解析，其中的花括号、运算符等会引发解析问题。

**替代方案：**
- 在 Astro 组件中定义脚本，在 MDX 中 import 引入
- 使用 `is:inline` 等 Astro 指令（如果是 Astro 环境）
- 将脚本提取到独立的 `.js`/`.ts` 文件中导入

## 3. 不要随意换行——换行生成 `<p>` 元素

**行为：** 在 MDX 中，一个空行会创建新的段落（`<p>` 标签）。即使在 JSX 元素内部，换行也可能被 MDX 解析器解释为段落内容。

**错误示例：**
```mdx
<div>
  第一行

  第二行
</div>
```
上面的空行会在 div 内部生成两个 `<p>` 元素，可能破坏布局（例如引入意外的 margin/padding）。

**正确写法（连续内容不换行）：**
```mdx
<div>
  第一行
  第二行
</div>
```
或者使用显式的 `<p>` 标签来控制。

**注意事项：**
- 在复杂的 JSX 布局中，尽量保持内容紧凑，避免无意义的空行
- 如果需要间距，使用 CSS（style/class）控制，不要用空行撑高
- 在列表、表格等结构中，空行也可能导致非预期的解析结果

### 3.1 区分软换行与段落边界——尤其 `<p>` 元素内部

**规则：** 在 MDX 中，**空行**才是段落边界（会把一段文本拆成多个 `<p>` 元素）；单个换行符（`\n`）通常是**软换行**（默认渲染为空格），不是段落边界。但 `<p>` 元素内部即使是软换行，也可能被解析器产生非预期的文本节点/换行，破坏内联布局，所以**如无必要不要在 `<p>` 内部换行**。

**错误示例（空行拆段）：**
```mdx
<p>
  第一句内容

  第二句内容
</p>
```
上面的空行会把内容拆成两个 `<p>` 段落，引入多余间距或破坏布局。

**建议写法（`<p>` 内保持单行）：**
```mdx
<p>第一句内容 第二句内容</p>
```

**注意：**
- 段落边界是**空行**，不是单个换行；真正要拆段时用空行，不应在单个 `<p>` 内靠换行实现。
- 即便如此，`<p>` 元素内部的普通换行符（`\n`）也可能被解析为软换行或产生非预期的文本节点，所以尽量把内容收进 `<p>` 单行。
- 需要视觉换行时，用显式的 `<br>` 或 CSS（`display: block`、`white-space`）控制，不要依赖裸换行。
- 纯 Markdown 段落（不带 `<p>` 标签的普通文本）里，单个换行默认是软换行（渲染为空格）；需要断行时用行尾两个空格或 `<br>`。

## 4. 其他常见陷阱

### 4.1 花括号 `{}` 的含义
在 MDX 中，`{}` 是 JSX 表达式，不是普通文本。如果需要显示字面量的花括号，需要转义或使用字符串：
```mdx
{/* 错误 */}
价格是 {100} 元

{/* 正确 */}
价格是 &#123;100&#125; 元
价格是 {'{100}'} 元
```

### 4.2 导入语句必须在顶部
`import` 语句应放在 frontmatter 之后、正文内容之前，且不能被任何内容打断。

### 4.3 组件命名
MDX 中使用的自定义组件必须以大写字母开头（React/JSX 规范）。

### 4.4 style 属性
MDX/JSX 中的 `style` 属性值必须是对象，不是字符串：
```mdx
{/* 错误 */}
<div style="color: red;">

{/* 正确 */}
<div style={{ color: 'red' }}>
```

## 5. 不要在 MDX 中使用 `<style>` 块

**原因：** MDX 解析器会把 `{...}` 当作 JSX 表达式交给 acorn 解析。CSS 大量使用 `{` `}` 语法(尤其是 `@keyframes` 的 `from { ... } to { ... }`、`@media (...) { ... }`、常规选择器块),会立即触发 acorn 解析失败:

```
Could not parse expression with acorn
MDXmicromark-extension-mdx-expression:acorn
```

**错误示例：**
```mdx
<style>
  @keyframes open {
    from { opacity: 0; }   /* ← acorn 试图把 { opacity: 0; } 当 JSX 表达式解析,失败 */
    to { opacity: 1; }
  }
</style>
```

**注意：** 不仅仅是 `@keyframes` —— **任何**包含 `{` `}` 的 CSS 块都会触发此错误,例如:
- 任何普通选择器 `selector { ... }`
- `@media (...) { ... }`
- `@supports ... { ... }`
- `:root { ... }`

所以在 MDX 中使用 `<style>` 块**实际上不可能**完全避免该错误,直接不用 `<style>` 块即可。

**替代方案：**
- **首选**:把样式移到该 slide 用到的 `.astro` 组件里。`.astro` 文件中的 `<style>` 由 Astro 框架专门处理(自动 scoped,不会污染全局 CSS),不会被 MDX 解析器看见
- **次选**:使用独立的 `.css` 文件,在 layout 中 `import` 引入
- **次选**:使用 inline `style={{...}}` 属性(仅适合简单样式)

## 快速检查清单

在保存 MDX 文件前，快速过一遍：

- [ ] 没有 `<!-- -->` HTML 注释
- [ ] 没有内联 `<script>` 标签
- [ ] JSX 布局内没有无意义的空行（避免意外 `<p>`）
- [ ] `<p>` 元素内部没有无意义的换行符（避免被解析为软换行/冗余节点）
- [ ] `style` 属性使用的是对象语法
- [ ] 没有内联 `<style>` 块（CSS 中的 `{}` 会被 acorn 当 JSX 表达式解析失败）
- [ ] `import` 语句都在顶部
- [ ] 花括号用途正确（表达式 vs 文本）
